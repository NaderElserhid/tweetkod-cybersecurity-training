::L2_07_Q1:: هاش طوله 40 خانة سداسية عشرية (مثل bd2e464b2e9f...) ينتمي إلى أي نوع؟ {
=SHA-1
~MD5
~SHA-256
~bcrypt
}

::L2_07_Q2:: لماذا كُسرت كلمات مرور alice وbob وcarla وdave بسرعة في مختبر Hashcat رغم استخدام هاش SHA-256؟ {
=لأنها كلمات موجودة في قائمة تخمين (wordlist) شائعة
~لأن الخادم التدريبي كان بطيئاً فسهّل الكسر
~لأن خوارزمية SHA-256 نفسها ضعيفة وقابلة للعكس مباشرة
~لأن طول كل كلمة مرور كان أقل من 6 أحرف
}

::L2_07_Q3:: ما وظيفة الملح (Salt) عند تخزين كلمات المرور؟ {
=قيمة عشوائية فريدة تُضاف لكل كلمة مرور قبل حساب الهاش فيختلف الناتج تماماً
~مفتاح تشفير سري يُستخدم لفك الهاش عند الحاجة
~قاعدة تمنع المستخدم من اختيار كلمة مرور قصيرة
~برنامج يُبطئ استجابة الخادم لإرهاق أي مهاجم
}

::L2_07_Q4:: لماذا تفشل جداول قوس قزح الجاهزة ضد كلمات مرور مملّحة (Salted)؟ {
=لأن الملح الفريد لكل مستخدم يجعل كل إدخال محسوب مسبقاً في الجدول عديم الفائدة
~لأن الجداول تحتاج تحديثاً دورياً من الشركة المصنّعة لم يحدث
~لأن SHA-256 لا يمكن حسابه إلا على خادم حقيقي متصل بالإنترنت
~لأن طول الهاش الناتج يتغيّر بعد إضافة الملح
}

::L2_07_Q5:: لماذا تُعتبر bcrypt وArgon2 خياراً أفضل من SHA-256 العادي لتخزين كلمات المرور؟ {
=لأنها مصمَّمة لتكون بطيئة عمداً فتجعل تجربة ملايين الكلمات مكلفة زمنياً للمهاجم
~لأنها تنتج هاشاً أقصر يسهل حفظه ومقارنته
~لأنها لا تحتاج أي ملح لتكون آمنة
~لأنها متوفرة فقط على خوادم ويندوز الحديثة
}

::L2_07_Q6:: ما الفائدة الأساسية لتحديد عدد المحاولات (Rate Limiting) وقفل الحساب (Lockout)؟ {
=يمنعان تجربة آلاف كلمات المرور تلقائياً على نفس الحساب خلال وقت قصير
~يجعلان كلمة المرور الحالية أطول وأقوى تلقائياً
~يستبدلان الحاجة لتفعيل التحقق بخطوتين (MFA)
~يحذفان الحساب نهائياً فور أول محاولة خاطئة
}

::L2_07_Q7:: كيف تُحسب الأولوية الحقيقية لإصلاح ثغرة في تقرير فحص الثغرات؟ {
=بضرب درجة الخطورة (Severity) في مدى التعرّض (Exposure) لمهاجم محتمل
~بترتيب ظهور الثغرة في التقرير من الأعلى إلى الأسفل فقط
~بعدد الأجهزة المتأثرة بها بغض النظر عن خطورتها
~بتاريخ اكتشاف الثغرة، فالأقدم اكتشافاً يُصلَح أولاً
}

::L2_07_Q8:: بين هذه الحالات، أيها تُصلَح أولاً حسب مبدأ خطورة × تعرّض؟ {
=ثغرة حرجة (Critical) على خادم مكشوف للإنترنت
~ثغرة متوسطة (Medium) على خادم داخلي فقط
~ثغرة منخفضة (Low) على جهاز تطوير داخلي معزول
~ثغرة عالية (High) على طابعة شبكة داخلية فقط
}

::L2_07_Q9:: ماذا يجب فعله مباشرة بعد تطبيق رقعة (Patch) لثغرة حرجة؟ {
=إعادة فحص النظام للتأكد من زوال الثغرة فعلاً، ثم توثيق ما حدث
~إغلاق التذكرة فوراً دون أي تحقق إضافي لأن الرقعة كافية وحدها
~حذف تقرير الفحص الأصلي حتى لا يظهر أي أثر للثغرة في السجلات
~الانتظار شهراً كاملاً قبل إعادة فحص النظام للتأكد
}

::L2_07_Q10:: ما أفضل ممارسة في إدارة الرقع (Patch Management) لحسابك اليومي على جهازك الشخصي؟ {
=استخدام حساب محدود الصلاحيات للاستخدام اليومي وتفعيل التحديث التلقائي
~استخدام حساب مسؤول (Administrator) دائماً لتسهيل كل التحديثات
~تعطيل التحديث التلقائي لتجنّب أي عطل غير متوقَّع
~الاعتماد على مضاد الفيروسات فقط دون تحديث نظام التشغيل
}
