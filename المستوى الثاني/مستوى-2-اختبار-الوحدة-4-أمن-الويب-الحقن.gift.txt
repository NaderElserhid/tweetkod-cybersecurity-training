::L2_04_Q1:: ما السبب الجوهري لحدوث حقن SQL؟ {
=دمج مدخل المستخدم مباشرة داخل نص الاستعلام دون فصل واضح بينه وبين بنية الأمر
~استخدام قاعدة بيانات قديمة الإصدار
~كتابة الاستعلام بلغة SQL بدل لغة أخرى
~تخزين البيانات في جداول متعددة بدل جدول واحد
}

::L2_04_Q2:: ما الحل الأساسي (الطبقة الأهم) للدفاع عن حقن SQL؟ {
=الاستعلام المُعامَل (Parameterized Query) الذي يفصل القيم عن بنية الأمر
~تغيير نوع قاعدة البيانات المستخدمة
~تشفير قاعدة البيانات بالكامل
~حذف كل رسائل الخطأ من الكود نهائياً
}

::L2_04_Q3:: لماذا تُعدّ صياغة f-string في بايثون (مثل <code>f"...\{name\}..."</code> داخل نص SQL) خطرة بدرجة الدمج النصي التقليدي؟ {
=لأنها تُدرج قيمة المتغيّر مباشرة داخل نص SQL قبل التنفيذ، دون فصل بين الأمر والقيمة
~لأنها أبطأ من الدمج النصي التقليدي بكثير
~لأنها غير مدعومة في النسخ الحديثة من بايثون
~لأنها تتطلب صلاحيات مدير لتعمل
}

::L2_04_Q4:: ماذا يفعل أمر <code>grep "'" /var/log/access.log</code> في سياق مراقبة سجل خادم؟ {
=يبحث عن الأسطر التي تحتوي على علامة اقتباس مفردة، وهي مؤشر شائع على محاولة حقن
~يحذف كل الأسطر التي فيها علامة اقتباس من السجل
~ينفّذ استعلام SQL مباشرة على قاعدة البيانات
~يوقف الخادم فوراً عند إيجاد نمط مشبوه
}

::L2_04_Q5:: في مختبر التحقيق بالسجل، ماذا دلّ تكرار عنوان IP واحد في عدة أسطر فيها علامات اقتباس وكلمة UNION؟ {
=نمط مريب يشير غالباً إلى محاولة حقن مركّزة من ذلك المصدر
~أن ذلك العنوان هو مسؤول الخادم يتفقد السجلات روتينياً
~أن هناك عطلاً في الشبكة يكرر الطلبات تلقائياً
~أن المستخدم نسي كلمة المرور وأعاد المحاولة فقط
}

::L2_04_Q6:: ما دور جدار حماية تطبيقات الويب (WAF) في الدفاع عن الحقن؟ {
=طبقة حماية إضافية تراقب الطلبات وتحظر الأنماط المعروفة، لكنها لا تُستبدل بإصلاح الكود
~يحل محل الاستعلام المُعامَل بالكامل فلا حاجة لتعديل الكود
~يشفّر الاتصال بين المتصفح والخادم فقط
~يمنع المستخدمين من كتابة أي علامة اقتباس في أي موقع
}

::L2_04_Q7:: ما فائدة مبدأ الصلاحية الأقل (Least Privilege) لحساب قاعدة بيانات التطبيق؟ {
=يحدّ من الضرر الذي يستطيع فعله مهاجم حتى لو نجح في استغلال ثغرة حقن
~يجعل الاستعلامات تنفّذ أسرع بشكل ملحوظ
~يمنع حقن SQL من الحدوث نهائياً دون أي طبقة أخرى
~يسمح للتطبيق بالاتصال بعدة قواعد بيانات دفعة واحدة
}

::L2_04_Q8:: ماذا يجب أن تعرضه رسالة الخطأ للمستخدم عند فشل استعلام قاعدة البيانات؟ {
=رسالة عامة مبسّطة، مع حفظ التفاصيل الدقيقة في سجل داخلي للمطورين فقط
~رسالة قاعدة البيانات الكاملة لمساعدته على فهم الخطأ
~رمز الاستعلام SQL كاملاً حتى يصلحه بنفسه
~إيقاف الموقع بالكامل حتى يُصلَح الخطأ
}

::L2_04_Q9:: ما التصرف الصحيح عند اكتشاف مؤشر على ثغرة حقن في موقع حقيقي أثناء التصفح العادي؟ {
=التوقف فوراً والبحث عن قناة الإبلاغ الرسمية عن الثغرات دون إرسال أي شيء إضافي
~تجربة استخراج بعض البيانات أولاً للتأكد من خطورة الثغرة
~نشر لقطة شاشة للمشكلة علناً لتحذير الآخرين فوراً
~تجاهل الملاحظة لأنها ليست مسؤوليتك
}

::L2_04_Q10:: أين يُفضَّل التدرب عملياً على اكتشاف ثغرات الحقن؟ {
=داخل منصات قانونية مثل DVWA في جهاز افتراضي معزول أو PortSwigger Web Security Academy
~على أي موقع حقيقي تختاره بنفسك طالما لا تضر به
~على خادم الإنتاج الحقيقي لشركتك مباشرة بعد ساعات العمل
~على أي تطبيق تجده بسرعة في نتائج البحث
}
