# دليل كتابة وحدة (TweetKod Design System v2)

كل وحدة = **ملف JavaScript واحد** في `_build-system/src/L1/NN-slug.js` أو `src/L2/NN-slug.js` يستدعي `TK.module({...})`.
البناء: `cd _build-system && python3 build.py L1 NN` (أو `L2 NN`) ← يفحص الملف (lint) ثم يولّد الـHTML الكامل + ملف GIFT في مجلد المستوى.
**المرجع الكامل الجاهز:** `src/L1/02-linux.js` — اقرأه أولاً وقلّده في الأسلوب والبنية.

## مبادئ المنهج (إلزامية)
1. **عملي أولاً.** الوحدة 90 دقيقة: النظرية ≤15 دقيقة (من 1 إلى 3 شرائح `TK.concept` فقط)، والباقي مختبرات وتحديات. كل موضوع: مفهوم ← مثال ← أداة ← مختبر ← تحدٍّ. اشرح **كيف ولماذا** تُستخدم الأداة، لا ما هي فقط.
2. **الحد الأدنى** (يفرضه lint): ≥3 مختبرات (`TK.lab` أو `TK.shell`)، ≥3 تحديات (`TK.challenge`)، ≥2 رسم متحرّك (`TK.steps`/`TK.terminal`/`TK.scan`/`TK.transform`)، ≥3 تحقّقات سريعة (`TK.check`)، 10 أسئلة اختبار بالضبط، ≥5 بنود في `audit`، ≥3 روابط في `resources`، ≥10 شرائح في `slides`.
3. **الفئة العمرية 13–18**: لغة واضحة ومباشرة، أمثلة من حياتهم (الألعاب، الجوال، حسابات التواصل، المدرسة)، جمل قصيرة، لا شرح نظري طويل.
4. **الأخلاقيات والسلامة:** كل تطبيق هجومي داخل **مختبر معزول** (VirtualBox/Host-Only، Metasploitable، DVWA، Juice Shop) أو منصة قانونية (picoCTF، TryHackMe، OverTheWire، Gandalf). ركّز في المواضيع الهجومية على الفهم والتحليل واكتشاف الثغرات وإصلاحها. لا تعليمات لاستهداف أنظمة حقيقية. لا تضع كلمات مرور أو بيانات حقيقية لأشخاص.
5. **لا تخترع حقائق:** لا إحصائيات ولا أسعار ولا مواعيد ولا أسماء حوادث إلا إن كنت متأكداً منها. استخدم الأدوات والروابط الحقيقية فقط (القائمة المسموحة أدناه).
6. **الأمور المنقولة من الوحدات القديمة:** تجد النسخة القديمة في `أرشيف-النسخة-القديمة/` (اقرأها لاستخراج الأفكار والتمارين الجيدة) — **لا تنسخ HTML القديم**، أعد كتابة المحتوى بمكوّنات المكتبة الجديدة وبتركيز عملي أكبر وبنظرية أقل.

## هيكل `TK.module`
```js
TK.module({
  id:'L1-03', level:1, num:3, slug:'كلمات-المرور-والمصادقة',     // slug عربي بشرطات، يدخل في اسم الملف
  title:'…', en:'…', emoji:'🔑', lead:'جملتان عن ما سيفعله الطالب (فعلياً)',
  tags:['🛠️ CyberChef'],                       // اختياري
  agenda:[{t:'💡 مفهوم سريع',time:'8 د'}, …],   // 4–7 عناصر، مجموعها ≈ 90 د
  slides:[ … ],                                // 10–24 نصاً HTML (انظر المكوّنات)
  quiz:[{q:'نص السؤال', ok:'الإجابة الصحيحة', no:['خطأ1','خطأ2','خطأ3'], why:'تفسير قصير'}, … ×10 بالضبط],
  // quiz اختيار من متعدد: كل عنصر {q, ok, no:[3 بدائل خاطئة], why}. اجعل البدائل الخاطئة معقولة (أخطاء شائعة)، لا سخيفة وواضحة البطلان.
  audit:['أنجزتُ …', …],                       // 5–8 مهام عملية يؤشّر عليها الطالب
  recap:['…','…','…'], homework:'…',
  resources:[{t:'اسم',u:'https://…'}, …], next:'جملة تشويق للوحدة التالية'
});
```
المحرك يضيف تلقائياً: شريحة العنوان، الخطة، ثم **شرائحك**، ثم الاختبار، قائمة الإنجاز، الملخص والمراجع، والختام. لا تكتبها بنفسك.

## الشرائح والمكوّنات (كلها دوال تُرجع نص HTML)
- `TK.s(عنوان, englishTitle, bodyHtml)` — الغلاف الأساسي لأي شريحة (يضيف h2). ضع العنوان بإيموجي في أوله (🎬 للحركة، 🧪 للمختبر، 🏁 للتحدي، 🎭 للسيناريو).
- `TK.concept({t,en,min,body,key})` — شريحة «مفهوم سريع» (1–3 فقط في الوحدة). `key` = الفكرة في جملة.
- `TK.breakSlide('نص عن الجزء القادم')` — استراحة 10 د بعدّاد (ضعها في منتصف الوحدة).
- `TK.table(['عمود',…],[[…],…])`، `TK.terms([['مصطلح','تعريف'],…])`، `TK.code('نص خام يُهرَّب تلقائياً')`، `TK.tool({e,n,what,why,how,url})`.
- `TK.recap(title, items)` شريحة تلخيص وسطية (اختياري).
- HTML عادي مسموح داخل `body`: `<div class="card">`, `<div class="grid g2|g3">`, `<div class="tip|note|warn">`, `<span class="code">`/`<code>`, `<span class="tag">`, `<ul class="clean"><li>`, `<p class="lead">`. **كل وسم يجب أن يُغلق** (lint يتحقق من توازن div/ul/table/dl/p/span/b/li/button لكل شريحة).

### المكوّنات التفاعلية
```js
// 1) حركة تنقّل بين طرفين: a يظهر على اليمين (بداية القراءة) و b على اليسار. at: 'a' | 'mid' | 'b'
TK.steps({ a:{e:'👩‍💻',l:'أنت'}, b:{e:'🖥️',l:'الخادم'},
  steps:[ {icon:'',at:'mid',cap:'الحالة الأولى'},
          {icon:'📨',at:'b',cap:'٢) …',ba:'شارة تحت a',bb:'شارة تحت b'},
          {icon:'✅',at:'a',cap:'٣) …',flash:'ok'|'bad'} ] })      // ≥3 خطوات، cap إلزامي
// at='b' يعني: الأيقونة تتحرك نحو الطرف b (يسار الشاشة). لا تقلق من RTL، المكتبة تتولاه.

// 2) بطاقات كشف (واحدة مفتوحة في كل مرة)
TK.cards({ cols:3, items:[{e:'🔒',t:'عنوان',b:'نص يظهر عند الضغط'}, …] })
// 3) مقارنة بزر تبديل (قبل/بعد، حقيقي/مزيّف). bad:true يلوّن اللوحة بالأحمر
TK.compare({ a:{t:'بدون VPN',html:'…',bad:true}, b:{t:'مع VPN',html:'…'} })
// 4) طرفية متحركة تعرض تنفيذ أداة (سطور: [نوع، نص، تأخير_اختياري_ms]) الأنواع: cmd out ok bad dim hl
TK.terminal({ title:'kali@lab', btn:'شاهد Nmap يعمل', lines:[['cmd','$ nmap -sV 192.168.56.101'],['out','PORT STATE SERVICE',500],['ok','21/tcp open ftp'],['dim','# ملاحظة']] })
// 5) مسح بصري (منافذ، ملفات…). s: open|closed|filtered|ok|bad
TK.scan({ cols:5, btn:'ابدأ الفحص', labels:{open:'مفتوح',closed:'مغلق',filtered:'مُرشَّح'}, cells:[{t:'21',s:'open',tip:'FTP'}, …] })
// 6) مُدخل ← آلة ← مُخرج. fn:'sha256' يحسب هاش حقيقياً؛ وإلا يُعرض output الثابت
TK.transform({ input:'Hello', label:'SHA-256', fn:'sha256', btn:'احسب', after:'جملة بعد الحساب' })
TK.transform({ input:"' OR '1'='1", label:'محرك قاعدة البيانات', gear:'🗄️', output:'تم تجاوز الدخول', editable:false })
// 7) مختبر بخطوات يؤشّر عليها الطالب (تُحفظ). tools = روابط. req/tip/warn اختيارية
TK.lab({ t:'عنوان المختبر', time:'10 د', req:'المتطلبات', steps:['خطوة 1 (HTML مسموح)','خطوة 2','خطوة 3'], tools:[{n:'اسم',u:'https://…'}], tip:'…', warn:'…' })
// 8) تحدٍّ بإجابة تُفحص فوراً (answer = نص أو مصفوفة بدائل؛ أو re = تعبير نمطي). pts افتراضي 10
TK.challenge({ t:'اسم', q:'السؤال/المهمة', answer:['FLAG{x}'], hint:'تلميح', explain:'شرح بعد الحل', ph:'FLAG{...}' })
// 9) سيناريو قرارات (ok:true للصحيح، fb إلزامي)
TK.scenario({ steps:[{ s:'الموقف…', o:[{t:'خيار',ok:false,fb:'لماذا خطأ'},{t:'خيار',ok:true,fb:'لماذا صحيح'}] }] })
// 10) تصنيف: اضغط عنصراً ثم الصندوق. b = رقم الصندوق، why/hint اختياريان
TK.classify({ buckets:[{t:'احتيال',e:'🚨'},{t:'حقيقي',e:'✅'}], items:[{t:'…',b:0,why:'…'}, … ≥4] })
// 11) أدوات حيّة جاهزة: 'hash' (SHA-256 حي) | 'entropy' (قوة كلمة المرور) | 'caesar' (عجلة قيصر) | 'convert' (Base64/Hex/Binary/ROT13)
TK.live('entropy')
// 12) تحقّق سريع صح/خطأ — ضعه بعد كل موضوع رئيسي لتنشيط الطالب أثناء الشرح (لا يُحتسب في الاختبار النهائي، فوري ومستقل عن quiz)
TK.check({ s:'عبارة واحدة قابلة للحكم عليها بصح أو خطأ عن الموضوع الذي شُرح للتو', t:true, why:'جملة تفسير قصيرة تظهر بعد الإجابة دائماً' })
```
**استخدام `TK.check`:** ضع واحداً مباشرة بعد كل `TK.concept` وبعد أي موضوع رئيسي آخر يستحق توقفاً سريعاً (≥3 في الوحدة، يُفضّل أكثر). عبارات عملية وواضحة بلا التباس، وازن بين صحيح وخاطئ، وتجنّب النفي المزدوج. هذا منفصل تماماً عن اختبار نهاية الوحدة (`quiz`) الذي يبقى اختيار من متعدد.

### TK.shell — طرفية Linux تفاعلية (أقوى مكوّن عملي)
نظام ملفات افتراضي كامل: `ls -la cd pwd cat head tail grep (-i -r -n) find -name wc sort uniq echo > >> mkdir touch rm cp mv chmod whoami id clear help` + أنابيب `|`.
```js
TK.shell({
  title:'student@lab: ~', user:'student', host:'lab', cwd:'/home/student',
  fs:{ home:{ student:{ 'notes.txt':'نص', '.hidden':'مخفي', docs:{'a.txt':'..'}, 'tool.sh':['echo hi','-rw-r--r--'] } }, var:{log:{'auth.log':'سطر1\nسطر2'}} },
  // نص = ملف، [نص, صلاحيات] = ملف بصلاحيات، كائن = مجلد
  tasks:[ {d:'اعرض الملفات: <code>ls</code>', re:'^ls\\s*$'} ],      // تُؤشَّر تلقائياً عند تطابق السطر المكتوب (regex)
  cmds:[ {re:'^nmap', out:'مخرجات أداة غير مدعومة مباشرة (محاكاة جاهزة)', cls:'ok'} ]   // أوامر مخصّصة بمخرجات ثابتة: nmap, ping, john, hashcat, steghide, exiftool, python…
})
```
- لمحاكاة أداة (Nmap، John، Steghide، Metasploit…) استخدم `cmds` بمخرجات **واقعية** ودقيقة، واجعل `re` مرناً (مثل `'^nmap\\s+(-sV\\s+)?192\\.168\\.56\\.101'`). يمكنك وضع عدة `cmds` لأنماط مختلفة، والأول المطابق يربح.
- المهام `tasks` يجب أن تكون قابلة للتنفيذ فعلاً بالأوامر المدعومة أو بـ`cmds` التي عرّفتها. اجعل نظام الملفات غنياً بأدلة يستخرجها الطالب (علم FLAG{...}، سجلات، ملفات مخفية…).
- التحديات `TK.challenge` تُبنى على ما يجده الطالب داخل الطرفية.

## قواعد اللغة العربية (الجودة أولاً)
- فصحى مبسّطة سلسة، موجّهة للطالب بصيغة المخاطَب («ستفعل»، «جرّب»). لا ترجمة حرفية. لا حشو.
- المصطلح الإنجليزي يُكتب مرة عند أول ذكر بين قوسين بعد العربي: «التصيّد الاحتيالي (Phishing)»، ثم يُستعمل العربي أو الإنجليزي باتساق. أسماء الأدوات والأوامر بالإنجليزية كما هي (`nmap`, `grep`).
- المصطلحات الموحّدة: Hash = بصمة/هاش · Encryption = تشفير · Vulnerability = ثغرة · Exploit = استغلال · Malware = برمجية خبيثة · Ransomware = برمجية فدية · Firewall = جدار حماية · Penetration Test = اختبار اختراق · Forensics = الطب الجنائي الرقمي · Incident Response = الاستجابة للحوادث · Flag = علم (Flag) · Lab = مختبر · Threat = تهديد · Authentication = المصادقة.
- لا تستعمل علامة الاقتباس المفردة المهرَّبة `\'` داخل أي سلسلة JS (تسبّبت بأعطال سابقاً): استعمل علامات الاقتباس المزدوجة أو القوالب `` ` `` للنص الذي يحوي فاصلة عليا. تجنّب `${` داخل القوالب النصية.
- الأرقام داخل الأوامر والشيفرات بالإنجليزية، والشرح بالعربية. وضع أمر داخل جملة عربية: `<code>nmap -sV x</code>`.
- لا تستعمل كلمات «بصراحة»/«حقاً» الحشوية ولا الإيموجي بكثرة (عنوان كل شريحة إيموجي واحد يكفي).

## الاختبار (10 عبارات صح/خطأ بالضبط)
quiz أصبح بصيغة صح/خطأ: كل عنصر `{s, t:boolean, why}` حيث `s` عبارة واحدة قابلة للحكم عليها بوضوح (وليست سؤالاً)، و`t` هل هي صحيحة أم خاطئة، و`why` جملة تفسير قصيرة تُعرض بعد الإجابة دائماً (صح أو خطأ). اجعل العبارات عملية/تطبيقية (ماذا يفعل هذا الأمر؟ ما نتيجة هذا الإجراء؟) أكثر من تعريفات نظرية جافة. وازن العدد تقريباً بين عبارات صحيحة وخاطئة (ليست كلها بنفس القيمة)، وتجنّب الصياغة السلبية المزدوجة ("لا يصحّ ألا...") لأنها تربك المبتدئين. لا تجعل الخطأ واضحاً بشكل سخيف — اجعله خطأً شائعاً ومنطقياً يقع فيه المبتدئ فعلاً.

## قبل أن تنتهي
شغّل `python3 build.py L1 NN` (أو L2) حتى يظهر ✔ بلا أخطاء. اقرأ ملفك مرة أخيرة بحثاً عن أخطاء إملائية وعن شرائح نظرية طويلة (قصّرها) وعن مهام shell لا يمكن تنفيذها. **لا تعدّل** `tk-lib.js` أو `tk-engine.js` أو `tk.css` أو أي وحدة غير وحدتك.
